# project3-wiki

주제: HVAC/시스템에어컨 설치자재 B2B 영업지원 — 오주문 손실을 줄이고 배송 완료율을
높이는 개선안을 검증하는 위키. 이 문서는 이 위키에서 작업할 때 지켜야 할 규칙을 정의한다.

**참고**: Day1 실습(`02_data/` 스키마 노트 9개)은 교안이 준 연습용 project3_growth
스키마(통신사 가입 퍼널)로 진행했다. Day2부터는 실제 도메인(HVAC 영업지원)의 BigQuery
데이터로 바로 작업한다 — `06_metrics/`·`01_questions/`은 전부 실제 데이터 기준이다.

## 폴더 구조

```
raw/            원본 데이터. 절대 수정하지 않는다.
00_inbox/       미분류 메모, 자유 형식 자료 요약, 검토 요청 메모
01_questions/   탐구할 질문
02_data/        raw 데이터의 스키마 노트
03_analysis/    질문에 답하기 위한 분석 "과정"(방법·판단 근거·한계). 결과 자체는 01_questions, 해석은 04_insights에 있으므로 중복 기재하지 않는다.
04_insights/    분석에서 얻은 인사이트
05_log/         날짜별 작업 로그
06_metrics/     지표 정의서. 지표 1개 = 파일 1개. 프론트매터는 계산 명세, 본문은 판단 근거와 한계.
99_sql/         질문에 답하기 위해 작성한 SQL 쿼리. 파일명은 관련 질문과 짝이 맞도록 `sql-` 접두사 + 질문 파일명
INDEX.md        전체 게이트웨이 노트. 데이터 카탈로그(전체)/검토 필요/최근 로그처럼 허브로 나누기 애매한 공통 섹션만 가진다.
나의_분석_워크플로우.md   Define→Acquire→Profile→Confirm→Clean→Model→Analyze→Validate→Publish→Approve&Send 10단계로 이 위키의 작업 절차를 기록하는 문서. 주차가 진행될 때마다 계속 갱신된다.
```

새 질문이 기존 허브 어디에도 깔끔하게 속하지 않으면(예: 새 주제축이 필요해 보이면) 억지로 기존 허브에 끼워 넣지 말고, 사용자에게 새 허브 신설 여부를 먼저 확인한다.

## 원본 자료 처리 규칙 (raw/ 동기화)

- `raw/`의 파일은 절대 수정하지 않는다. 원본 그대로 보존한다.
- `raw/`에 새 파일이 추가되면, 먼저 `raw/` 파일 목록과 `02_data/`, `00_inbox/`의 노트 목록을 **파일명 기준으로만** 대조한다. 내용은 읽지 않는다.
- 이미 대응하는 노트가 있는 파일은 다시 읽지 않는다 (토큰 낭비 방지).
- 대응 노트가 없는 새 파일만 실제로 읽어서 분류한다.
  - 표 형태 데이터 → `02_data/`에 스키마 노트 생성
  - 표가 아닌 자유 형식 자료(메모, 텍스트 등) → `00_inbox/`에 요약 노트 생성
  - 내용이 불분명해서 분류 판단이 어려우면 **추측해서 노트를 만들지 않는다**. `00_inbox/`에 검토 요청 메모를 남긴다.
- 생성한 노트에는 반드시 `source: [[raw/원본파일명]]`을 남긴다.
- 공통 컬럼이 있는 데이터끼리는 위키링크로 서로 연결한다.

## 노트 작성 규칙

- 모든 노트 상단에는 YAML 프론트매터로 날짜·분류·관련 데이터 등 메타데이터를 포함한다.
- 주제 태그(`tags`)를 프론트매터에 추가한다.
- 인사이트 노트는 **근거 → 해석 → 시사점** 순서로 작성한다.
- 노트 간 연결은 Obsidian 위키링크 `[[파일명]]` 형식을 사용한다.
- 추측과 사실을 명확히 구분한다. ("~로 보임" vs "~임")
- 새 질문·분석·인사이트·SQL 노트가 생성될 때마다, 주제가 속하는 허브 노트의 해당 섹션에 링크를 추가한다. 두 허브에 걸치는 내용이면 양쪽 허브 모두에 추가하고, 각 허브의 "연결" 섹션에도 상호 참조를 남긴다.
- `00_inbox/`·`02_data/`(스키마 노트)는 `INDEX.md`의 `## 검토 필요` / `## 데이터`에 직접 링크한다 — 두 허브가 공유하는 성격이라 특정 허브에 종속시키지 않는다.

각 노트 유형의 프론트매터 항목과 본문 구성은 `01_questions/_template.md`, `04_insights/_template.md`를 따른다.

## 작업 로그 규칙

세션이 끝나면 `05_log/오늘날짜.md`에 이번 세션에서 처리한 raw 파일과 생성한 노트 목록을 요약해서 기록하고, `INDEX.md`의 `## 최근 로그` 섹션에도 링크를 추가한다.

## 분석 기준

- 표본 30건 미만 세그먼트는 참고용으로만 사용하고, 결론의 근거로 쓰지 않는다.

## 컬럼 표는 기계가 읽는 구역이다

실물 파일에 실제로 있는 컬럼만 적는다. 설계상 있었으나 실물에 없는 컬럼을 취소선으로 남기거나, 계획 중인 컬럼을 미리 적지 않는다. 실물과 다른 점은 본문의 "실물 대조" 절에 쓴다.
