## 프론트매터 작성 규칙

계산 자동화 대응 — 아래 필드는 문서가 아니라 실행 명세다. 새 지표는 이 형식만 지키면 코드 수정 없이 계산된다.

**기초 지표 (카운트형·금액형)**

```yaml
계산:
  원천: "테이블A + 테이블B"      # 여러 개면 " + "로 나열
  집계: "SUM(테이블A.컬럼)"       # 집계함수 + 대상 컬럼
  조인: "테이블A.키 = 테이블B.키"  # 원천 2개 이상이면 필수
  조건: "테이블A.컬럼 = @placeholder"   # 순수 SQL WHERE 절 (한국어 설명 금지)
  산식: "..."                     # 사람이 읽는 설명. 계산에는 쓰지 않음
```

**비율형** — 다른 지표를 참조하지 않고 분자·분모를 각자 원천에서 직접 집계한다.

```yaml
계산:
  분자: { 원천: "...", 집계: "...", 조건: "..." }
  분모: { 원천: "...", 집계: "..." }
```

**파생형** — 분자·분모가 다른 지표다. `[[metric_id]]` 링크로 쓰면 자동으로 의존 관계가 해석된다.

```yaml
계산:
  분자: "[[metric_id]] — 설명"
  분모: "[[metric_id]] — 설명"
```

**변화율형** (파생형의 특수 형태) — 같은 지표의 서로 다른 두 시점을 비교한다. 분자·분모가 아니라 `기준지표`와 `시차`를 선언한다.

```yaml
계산:
  기준지표: "[[metric_id]]"
  시차: -3
  방향: 감소
  산식: "..."
```

`계산.시차`가 있으면 스크립트가 변화율형으로 판별한다. metric_id 화이트리스트가 아니라 명세로 판별하므로 새 변화율 지표를 추가할 때 코드를 고치지 않는다.

주의할 점:

- `조건`은 실행되는 SQL이다. 테이블이 2개 이상이면 컬럼을 테이블명으로 한정해야 한다.
- 시간 조건이 없는 지표는 `기간.자리표시자: "없음"`으로 선언한다. 선언과 실제 SQL이 어긋나면 실행이 중단된다.
- 필드가 빠지면 조용히 넘어가지 않고 실행 전체가 실패한다. 무인 실행 중 잘못된 값이 섞이는 것보다 낫다는 판단.
