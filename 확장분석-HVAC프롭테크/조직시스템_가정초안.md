# 조직·시스템 가정 초안 (⚠️ 전부 추정 — 실제 확인 전까지 사실로 취급 금지)

**작성일**: 2026-08-01
**목적**: [데이터_적재_요청서.md](데이터_적재_요청서.md)의 "확인 필요" 2건에 답하기 위해, 이 업종(HVAC/B2B 시스템에어컨 설치자재 유통·영업지원)에서 **일반적으로 흔한 조직·시스템 구조**를 근거로 가정을 채운 초안이다.

**전제**: 나는 이 회사의 실제 조직도·시스템명·담당자를 전혀 모른다. 아래 내용은 "이런 업종에서는 보통 이렇게 되어 있다"는 업계 통념에서 추론한 것이지, 이 회사를 조사해서 나온 사실이 아니다. **사용자님이 실제와 대조해 고치는 용도로만 쓸 것.**

---

## 1. 가정한 조직도

```
영업본부 (가정)
├─ 영업기획팀        — 가격정책·할인율 승인, 거래선 계약조건 관리
├─ 영업지원팀 ★      — 사용자 소속 추정: 발주서 처리·오주문 모니터링·해피콜
├─ 구매팀(자재팀)    — 공급사 협상·구매단가 관리
├─ 물류팀            — 배송·창고·직배송 관리
└─ IT전산팀          — ERP/시스템 운영·데이터 추출
```

**근거(추론 방식)**: `합성데이터` 작업 중 할인율 승인자로 넣었던 "영업기획팀"이라는 표기, 그리고 사용자님이 밝힌 실제 업무(발주서/오주문/해피콜)가 전형적인 "영업지원팀" 업무 범위와 일치한다는 점에서 역산했다. **실제 팀 이름이 다를 가능성이 높다** (예: "영업관리팀", "CS팀", "고객지원팀" 등으로 불릴 수도 있음).

## 2. 가정한 시스템 랜드스케이프

| 시스템(가정) | 보통 담당하는 데이터 | 이 회사에 있을 가능성 |
|---|---|---|
| **ERP** (더존/SAP B1/영림원 등 중소·중견 유통업 흔한 솔루션 중 하나로 추정) | 판매주문, 구매주문, 재고, **거래처마스터**(거래선 코드·명·**주소**·담당자) | 높음 — 배송지 입력이 업무상 필수라 주소 필드는 보통 이미 존재 |
| **CRM/SFA**(영업관리시스템) | 거래선 상세 이력, 방문기록, 계약조건 | 중간 — 중소 유통업은 별도 CRM 없이 ERP로 대체하는 경우도 흔함 |
| **WMS**(창고관리시스템) | 출고·재고·배송상태 | 낮음~중간 — 직배송 비중이 크면 자체 WMS 없이 공급사 물류에 의존할 수도 있음 |
| **그룹웨어** | 할인율 승인 등 내부 결재 이력 | 높음 |

## 3. "확인 필요" 2건에 대한 추정 답변

### ① 요청서 수신 담당 팀 (원본: "정확한 담당 팀은 확인 필요")

**추정 답변**: 데이터 추출 실무는 **IT전산팀**, 할인율·가격 데이터의 내용 승인은 **영업기획팀**이 공동으로 관여할 가능성이 높다. 순수 데이터 추출만 필요하면 IT전산팀에 먼저 요청하고, 가격/할인율 관련 항목은 영업기획팀 확인을 거치는 2단계 구조를 가정.

### ② 거래선-지역 매핑 위치 (원본: "CRM/거래처 관리 시스템 어디에 있는지 확인 필요")

**추정 답변**: **ERP의 거래처마스터에 이미 존재할 가능성이 가장 높다.** 판매주문을 처리하려면 배송지 주소가 필수 입력 항목인 경우가 대부분이라, 시군구 단위 주소가 이미 어딘가에 저장돼 있을 것으로 추정한다. 별도 CRM이 있다면 거기에 더 상세한 위치정보(방문좌표 등)가 있을 수 있으나, 없어도 ERP 거래처마스터만으로 시군구 매핑은 충분할 것으로 본다.

## 4. 사용자님이 실제로 확인·보완해야 할 점

위 추정이 틀렸을 가능성을 염두에 두고, 아래를 실제로 확인해주셔야 한다:

1. **조직도 대조** — 위 5개 팀 이름·구성이 실제와 맞는지. 특히 본인이 속한 팀 이름이 "영업지원팀"이 맞는지, 해피콜이 별도 CS팀 소관은 아닌지.
2. **ERP 시스템명 확인** — 사내에서 실제 쓰는 시스템 이름(예: 더존 스마트A, SAP, 자체개발 등)을 알아야 IT전산팀에 정확한 요청이 가능함.
3. **거래처마스터에 주소 필드가 실제 있는지** — ERP 화면에서 거래처 조회 시 주소/배송지 컬럼이 보이는지 직접 확인. 있다면 이번 "확인 필요" 항목은 바로 해결됨.
4. **할인율 승인권자 확인** — `dim_discount_policy`에서 가정한 "영업기획팀 승인"이 실제 프로세스와 맞는지(결재 시스템에 승인 이력이 남아있을 것).
5. **구매팀/물류팀의 실제 존재 여부** — 회사 규모가 작으면 이 기능들이 영업지원팀에 통합돼 있을 수도 있음(사용자님이 구매단가·배송까지 겸하고 있을 가능성).

## 5. 위 확인 결과에 따라 추가로 요청해야 할 데이터

| 확인 결과 | 추가로 받아야 할 데이터 |
|---|---|
| 조직도가 위 가정과 다름 | 실제 조직도(팀명·업무분장) 1부 — 데이터 요청 시 어느 팀에 보낼지 정확히 알기 위함 |
| ERP에 거래처 주소 필드 있음 | 거래처마스터 **전체 export**(거래선코드·명·**주소**·담당자·거래상태) — [수집필요_데이터_리스트.md](../수집필요_데이터_리스트.md)의 ①거래선 마스터가 이걸로 바로 채워짐 |
| ERP에 거래처 주소 필드 없음 | 주소 정보가 아예 없다는 뜻이므로, 영업사원별로 담당 거래선 주소를 **새로 수집**해야 함(엑셀로 한 번 취합하는 작업 필요) |
| CRM이 별도로 존재함 | CRM의 거래선 상세 데이터도 함께 요청(ERP보다 최신·상세할 가능성) |
| 할인율 승인 프로세스 문서 존재 | 승인 이력(거래선×자재군×할인율×승인일) — 이게 있으면 [수집필요_데이터_리스트.md](../수집필요_데이터_리스트.md)의 ⑤거래선별 할인율 정책을 실제 값으로 바로 교체 가능 |
| IT전산팀에 ERP 필드 정의서 존재 | ERP 데이터 딕셔너리(컬럼명·타입·코드값 의미) — 앞으로 어떤 데이터를 요청하든 매번 필요하므로 가장 먼저 확보할 가치가 큼 |

**우선순위 제안**: 5번(ERP 필드 정의서)을 가장 먼저 확보하는 걸 추천한다. 이게 있으면 이후 모든 데이터 요청(판매주문·구매단가·할인율 등)을 정확한 컬럼명으로 요청할 수 있어, 반복적으로 "그게 어디 있는지 확인 필요"를 겪지 않아도 된다.
